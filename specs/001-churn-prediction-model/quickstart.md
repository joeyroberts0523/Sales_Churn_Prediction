# Quickstart: Customer Churn Prediction Model

**Feature**: 001-churn-prediction-model  
**Date**: 2026-02-09

## Prerequisites

- Access to Microsoft Fabric workspace with Data Science and Data Engineering capabilities
- Power BI Pro license for dashboard publishing
- Python 3.11+ (built into Fabric notebooks)
- Git for version control

## Environment Setup

### 1. Clone Repository

```bash
git clone https://github.com/joeyroberts0523/Sales_Churn_Prediction.git
cd Sales_Churn_Prediction
git checkout 001-churn-prediction-model
```

### 2. Fabric Workspace Setup

1. Navigate to your Fabric workspace
2. Create a new **Lakehouse** named `churn_lakehouse`
3. Import notebooks from `notebooks/` folder
4. Create a new **Environment** with the following packages:

```yaml
# environment.yml
dependencies:
  - scikit-learn>=1.3.0
  - pandas>=2.0.0
  - numpy>=1.24.0
  - scipy>=1.11.0
  - mlflow>=2.8.0
  - great-expectations>=0.18.0
  - matplotlib>=3.7.0
  - seaborn>=0.12.0
```

### 3. Lakehouse Tables

Create the following Delta tables in `churn_lakehouse`:

| Table | Description | Initial Load |
|-------|-------------|--------------|
| customers | Customer master data | From source system |
| customer_activity | Activity history | From source system |
| churn_events | Historical churn labels | Manual/ETL |
| features | Feature store | Generated by notebook |
| predictions | Model predictions | Generated by notebook |
| model_metrics | Performance tracking | Generated by notebook |
| feature_importance | Feature analysis | Generated by notebook |
| policies | Policy definitions | Manual entry |
| policy_cohorts | Policy assignments | Manual/automated |

## Development Workflow

### Running Notebooks (First Time)

Execute notebooks in order:

```
1. 01_data_exploration.ipynb     → Understand data, identify issues
2. 02_feature_engineering.ipynb  → Create features table
3. 03_model_training.ipynb       → Train model, log to MLflow
4. 04_model_evaluation.ipynb     → Validate performance
5. 05_batch_scoring.ipynb        → Score all customers
6. 06_feature_importance.ipynb   → Generate importance report
7. 07_policy_monitoring.ipynb    → Policy efficacy analysis
```

### Weekly Scoring (Production)

For weekly batch scoring, run only:
```
05_batch_scoring.ipynb
```

This notebook:
1. Loads latest customer features
2. Applies registered MLflow model
3. Outputs predictions to `predictions` table
4. Updates `model_metrics` with production performance

### Retraining (As Needed)

When retraining is required:
```
02_feature_engineering.ipynb  → Refresh features with new data
03_model_training.ipynb       → Train new model version
04_model_evaluation.ipynb     → Validate before production
```

Register new model in MLflow only if AUC-ROC ≥ 0.70.

## Configuration

### Risk Tier Thresholds

Edit in `src/scoring/risk_tiers.py`:

```python
RISK_THRESHOLDS = {
    "Low": (0.0, 0.30),
    "Medium": (0.30, 0.50),
    "High": (0.50, 0.70),
    "Critical": (0.70, 1.0)
}
```

### MLflow Experiment

Set experiment name in notebooks:
```python
mlflow.set_experiment("churn-prediction-001")
```

### Data Freshness

Minimum data requirements in `src/data/validation.py`:
```python
MIN_HISTORY_MONTHS = 18
MIN_TRAINING_ROWS = 10000
MAX_DATA_AGE_DAYS = 7  # Weekly refresh
```

### Data Validation

Run Great Expectations suite:
```python
# In notebook or script
from great_expectations.data_context import DataContext
context = DataContext("tests/data_quality/great_expectations")
context.run_checkpoint("churn_data_validation")
```

### Model Validation

Before deploying a new model:
1. AUC-ROC ≥ 0.70 on holdout test set
2. Feature importance coefficients have expected signs
3. No data leakage (future information in features)
4. Predictions distribution is reasonable (not all same tier)

## Troubleshooting

### Common Issues

| Issue | Solution |
|-------|----------|
| Low AUC-ROC | Check for class imbalance, verify features have predictive power |
| Missing predictions | Verify customer_id exists in both customers and features tables |
| Stale data | Check data_freshness validation, ensure weekly ETL completed |
| MLflow errors | Confirm experiment exists, check workspace permissions |

### Logs

- MLflow runs: Fabric MLflow UI under workspace experiments
- Notebook execution: Fabric monitoring
- Data validation: Great Expectations data docs
